# 状态栏设计基线

> 回答一个问题：**自绘状态栏长什么样、每一段说什么、图标从哪来、窄了怎么办。**
>
> 这份文档是状态栏的**口径来源**。实现与文档冲突时，先改文档再改实现，
> 或者改实现时同步改文档 —— 不留"文档说一套、代码做一套"的段。

---

## 1. 定位与范围

状态栏是自绘 chrome 的最下一条（`StatusBar` 自绘 HWND，不进 DUI），承担三件事：

1. **计数与状态**：文件夹 / 文件 / 已选 / 修改日期 / 选中容量 / 容器容量 / 隐藏三态 / 类型
2. **当前位置**：路径段（带当前文件夹的真实系统图标）
3. **入口**：左键直接触发段动作，右键开段显隐菜单

**不归状态栏**：搜索框、筛选器、排序菜单、视图模式按钮 —— 这些属于导航栏 / 标签栏。
（Windhawk 的 `ebstatus` 把"视图模式按钮区"塞在状态栏右端，本仓没有照搬：
本仓视图模式在导航栏右侧，状态栏右端留给容量与磁盘。）

### 1.1 段的定义

`src/status_bar.h` 里的 `SegId` 是**唯一**的段编号来源，顺序固定：

| 段 | 枚举 | 位置组 | 说的��� | 点击动作 |
|---|---|---|---|---|
| 文件夹计数 | `Seg_Fld` | 左 | `文件夹 选中/总数` | — |
| 文件计数 | `Seg_File` | 左 | `文件 选中/总数` | — |
| 已选/总数 | `Seg_Chk` | 左 | `已选 N/总数` | 全选 / 取消全选 |
| 修改日期 | `Seg_Date` | 左 | 最新修改时间，无则 `—` | 按修改日期排序 |
| 路径 | `Seg_Path` | 中（弹性） | 当前目录名 + 真实系统图标 | 复制路径 |
| 选中容量 | `Seg_Size` | 右 | `选中 <容量>` | 属性 |
| 容器/磁盘 | `Seg_Disk` | 右 | `磁盘 X 可用 / Y` | 打开"此电脑" |
| 隐藏文件三态 | `Seg_Eye` | 右 | `全显` / `隐系统` / `隐全部` | 三态循环 |
| 类型 | `Seg_Type` | 右 | 选中项扩展名 / `多种类型` | — |

**段是"语义"不是"装饰"**：一个段被关掉（`statusSegs`）就是整段消失，
不留空槽、不留图标。

## 2. 图标口径（核心）

### 2.1 原则

**段的图标用系统默认图标。** 三级取用链，逐级降级：

```
1. SHGetStockIconInfo(SIID_*)   —— 公开、稳定、随系统主题变
        ↓ 取不到
2. 系统 DLL 的序号资源           —— shell32 / imageres 的图标序号
        ↓ 取不到
3. Segoe Fluent Icons 字形       —— 系统字体，仍是"系统默认"的形状
```

第 3 级不是自绘图标，是**系统字体的字形**，和第 1/2 级同属系统资源。
定这条链的原因：DOpus / XYplorer 的状态栏图标全是系统图标，
Windhawk 的 `ebstatus` 也是（`shell32,3` / `imageres,228` …），
本仓跟同一口径 —— 用户不会觉得"这是另一个软件画的"。

### 2.2 已验证的映射表

系统位图部分（**逐个导出 PNG 肉眼核对过**，不是照抄网上表格）：

| 段 | 取用方式 | 实际形状 |
|---|---|---|
| 文件夹计数 | `SIID_FOLDER` | 扁平打开的黄色文件夹 |
| 文件计数 | `SIID_DOCNOASSOC` | 白色文档 |
| 已选/总数 | `imageres.dll` 序号 **228** | 绿色圆圈对勾 |
| 选中容量 | `imageres.dll` 序号 **203** | 带蓝绿底座的立体文件夹（Windows 的"文件夹 + 度量"位图，Windhawk 同口径） |
| 容器/磁盘 | `imageres.dll` 序号 **30** | 灰色硬盘 + 绿色指示灯 |
| 路径 | `ico::Cached(当前目录)` | 当前文件夹的**真实**系统图标 |

**系统里没有的形状**（扫过 `shell32` 0..130 与 `imageres` 0..130 全部序号，确认无对应位图）：

| 段 | 降级到字形 | 码位 | 核对结果 |
|---|---|---|---|
| 修改日期 | `IconId::Calendar` | `U+E787` | 带格子的月历 ✔（导出 PNG 确认） |
| 隐藏文件三态 | `IconId::Eye` | `U+E7B3` | Fluent View：弧线 + 瞳孔 ✔ |
| 类型 | `IconId::Tag` | `U+E8EC` | 标签 ✔ |
| 选中容量 | `IconId::HardDrive` | `U+EDA2` | 扁平机身 + 指示灯 ✔ |

> **一处纠错**：Windhawk `Exbar.cpp` 的注释把 `shell32,249` 说成"日历"，
> 实测那是**时钟**。本仓不跟这个注释 —— 日期段用 `U+E787` 字形，
> 而不是一枚会被误读成时钟的位图。

> **为什么容量段不跟文件夹计数共用一枚图标**：两段图标一样，用户分不出
> "这是文件夹数" 还是 "这是占多大"。容量段用 `imageres,203`
> （立体 + 底座），与 `SIID_FOLDER`（扁平打开）在 16px 下仍能分开；
> 位图取不到时退 `U+EDA2` 硬盘字形，同样不撞文件夹。

### 2.3 稳定性约束

- `SIID_*` 是公开文档化的常量，**稳定**，首选。
- DLL 的**序号资源**（`shell32`/`imageres` 的第 N 号图标）**跨 Windows 版本不稳定** ——
  序号会随系统更新重排。所以序号只作"取得到就用"，**取不到必须静默降级**，
  绝不假设它一定存在。
- 因此 `sys_icon::Get()` 返回空是**正常路径**，不是错误：
  调用方拿到空就退字形，不弹窗、不记错。

### 2.4 唯一映射源

段 → 图标只有**一份语义**、**两份映射**，成对维护：

```cpp
ico::IconId  StatusSegmentIcon(int seg);    // 没有系统位图时用哪个字形
sysicon::Id  StatusSegmentSysId(int seg);   // 有没有系统位图、用哪张
```

**状态栏本体与状态栏右键菜单共用这两个函数**（`src/app_commands.cpp` 的 `ShowStatusMenu`）。
少一对就是"同一段在栏上长一个样、在菜单里长另一个样"。

### 2.5 生命周期

`src/sys_icon.*` 是**系统图标的唯一取用口**：

- 进程级缓存，句柄由它自己持有与销毁
- 主题切换时 `Invalidate()` 丢弃旧句柄，下次 `Get()` 重新取
- 路径段的图标是**借用** `ico::Cached` 的进程级缓存，调用方不销毁

## 3. 排版规则

### 3.1 三段式

```
[ 左组：计数/日期 ]   [ 路径（弹性，占剩余空间） ]   [ 右组：容量/磁盘/三态/类型 ]
```

- 左组：从左边缘起排，顺序 = 段编号顺序
- 路径：**唯一**占中间弹性位的一段
- 右组：从右边缘**回填**（右对齐），顺序 = 段编号顺序

> **路径段只画一次。** 它归中间位，不进右组。
> （早期实现右组过滤条件只排了 `seg <= Seg_Date`，路径段编号 4 > 3 于是被右组又收了一份，
> 同一段画两遍、右组还白占一份宽度。已修，见 §6.3。）

### 3.2 宽度的"不抖"

数值段（计数、容量、磁盘）的宽度按**位数**算，不按当前值算：

```cpp
// 把数字换 '8' 再量宽 —— 宽度只跟位数走
ui::MeasureStableText(dc, font, text);
```

三种口径对比：

| 口径 | 行为 | 判定 |
|---|---|---|
| 按当前值量 | 1 → 10 时整段宽度跳一下 | ✗ 抖 |
| 历史最大宽（早期实现） | 只增不减，进过一次大目录后该段永久偏宽 | ✗ 白占地方，窄窗口下挤掉别的段 |
| **按位数量**（现行） | 只在位数变化时变 | ✔ |

`ui::MeasureStableText` 放在 `src/ui_draw.cpp`（量字原语只此一处，
`GetTextExtentPoint32W` 也不得出现在别处）。

### 3.3 窄窗口的丢弃顺序

宽度不够时按固定顺序丢段，**每丢一段都重算**：

```
类型 → 隐藏三态 → 磁盘 → 选中容量 → 日期
```

- 丢的是**右组优先**，最后才动日期
- 路径段永远不丢：它拿剩余空间，不够 120px 就**整段不画**
  （画半截路径比不画更糟 —— 看不出在哪）
- 早期实现是"一刀切删 `Seg_Eye` 及之后"，既没重算宽度、
  又让日期被压成负宽，窄窗口下所有段叠在同一个矩形里。已修。

## 4. 交互规则

### 4.1 左键

段 = 一个动作入口（见 §1.1 表）。**点击语义要可预期**：
计数段点击要么全选要么排序，不做"点了没反应"。

### 4.2 右键

右键开**段显隐菜单**：9 个段各一行，**勾选列**表示"开着"，行首图标 = 状态栏上那一枚。
菜单底部是「复制当前路径」「隐藏状态栏」。

菜单动作号与段号**显式分段**（`kCopyPath = 100` / `kHideStatusBar = 101`）——
靠"100 不会和段下标撞"这种隐式约定，加一项就可能静默错位。

#### 勾选态的画法：左独立列，不是"文字前缀"

**行业标准**（本项目是 Windows 平台，跟 Win32 / Fluent 口径，不跟 macOS）：

| 来源 | 勾号位置 | 口径 |
|---|---|---|
| Win32 `HMENU` + `MFT_CHECK` | 菜单**最左侧独立一列**（gutter） | 系统绘制，整列对齐；没有可勾选项时该列不出现 |
| Windows 11 Fluent 菜单 | 同 Win32，左 gutter | 系统同源 |
| W3C ARIA `menuitemcheckbox` | grid **第一格**（独立单元格） | 勾号不是文案的一部分 |
| macOS / VS Code | **右侧** | 不采用（非 Windows 平台口径） |
| Directory Opus / XYplorer | 左侧 gutter | 与 Win32 一致 |

**旧口径（已废）**：`label = "✓ " + 文案`，未勾选行用三个 ASCII 空格占位。三个问题：

1. `"✓"` 走**正文字体**（Segoe UI 的 U+2713），不是系统的勾形字形 —— 粗细、弧度
   跟同一行的 Segoe Fluent Icons 图标不是一个体系，看着像"外挂"的。
2. 空格比 `✓` **窄**，于是勾选行与未勾选行的文字**横向对不齐**（差一个勾号宽）。
3. 勾号混进文案，弹层量宽时把它算进文字，同一列的宽度忽宽忽窄。

**现口径**：勾选态是 `PopupRow::checked` 这个**独立字段**（不是文案的一部分），
勾号画在弹层**最左侧的一整列**，用系统字形 `ico::IconId::Check`
（Segoe Fluent Icons U+E73E，与同行的图标同一字体、同一尺寸）。

- 整列**要么全在要么全不在**：只要有一行可勾选就留整列（`HasCheckedRow`），
  否则勾号会忽左忽右。没有可勾选项时这一列不出现（不留空槽）。
- 未勾选的行在同一列**留空**（不用空格占位）—— 留空是"这一格没勾"，
  空格占位是"这一格有一个看不见的东西占着宽度"，后者会把文字挤歪。
- 勾选列宽 = 图标槽宽（`PopupCheckColWidth`），两列等宽才不别扭。
- 弹层宽度计算要把勾选列算进去，否则勾号会被右边距压掉（`PopupMeasureWidth`）。

实现落点：`src/menu.{h,cpp}`（内容层，置 `checked` 字段）→
`src/popup_list_draw.{h,cpp}`（绘制层，画那一列）。

### 4.3 悬停

- 悬停段有背景高亮
- 气泡提示：`tip[seg]` 优先，没有则用 `text[seg]`
- 气泡走 `ui::TooltipHost`（唯一实现，不在状态栏里另写一份 TTM_ 样板）

### 4.4 输入纪律

状态栏是自绘 HWND，鼠标事件先过 `MouseSink`（`MT_STATUS` / `MT_STATUS_SEG` 两个 target），
再落到段动作。**不合成鼠标事件**：开发期截图走 `scripts/shot.py` 的 PrintWindow，只读。

### 6.5 单测覆盖

`tests/status_bar_test.cpp`（不碰窗口，纯函数自测）钉死三条不变量：

1. **每段必有图标**：除路径段（用当前目录的真实系统图标）外，每段都要么有系统位图、
   要么有字形兜底 —— 两者皆空就是空图标槽。
2. **段位图不撞车**：文件夹计数 / 容量 / 磁盘三段的位图互不相同，
   否则用户分不出"几个文件夹"和"占多大"。
3. **宽度按位数**：同位数不同数字宽度不变（不抖），多一位宽度变大。

> 改了段的图标口径，这三条会红 —— 这是故意的。
