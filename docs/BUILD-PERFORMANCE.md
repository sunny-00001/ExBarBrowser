# 构建与并行开发性能优化

> 本文记录 2026-11-24 对构建系统的性能诊断、改动与实测数据。
> 结论先行：**真正的成本不在链接，也不在日常增量，而在冷编译与多会话重复编译。**

## 1. 诊断：时间花在哪（实测，16 核 / 16 GB / clang 20.1.3）

| 场景 | 耗时 | 说明 |
|---|---|---|
| 无改动增量 | 0.6s | 只重新链接；165 个 TU 全部跳过 |
| 改一行 | ~1.1s | 只重编 1 个 TU |
| 冷编译 `-j 8`（旧默认） | 37.2s | PCH 6s + 165 TU 编译 ~31s + 链接 |
| 冷编译 `-j 16` | 29.5s | 满核，比 -j8 快约 20% |
| 链接 GNU ld | 0.49s | — |
| 链接 lld | 0.31s | 快约 40%，但绝对值小 |

修正两个常见误解：

- **链接不是瓶颈**（0.3–0.5s），优化它收益极低。
- **日常增量已经很快**（<1s），再往下优化空间有限。

真正的浪费有两处：

1. 默认 `-j 8` 在 16 核机器上浪费一半并行度；
2. 高并发多会话各用独立 `--objdir`，**同一批 165 个 TU 被每个会话各编一遍**——
   实测 4 个会话就是 4×30s 的 CPU + 4×100 MB 的 obj。

## 2. 已落地的改动

### A. 并行度自适应 + lld（`build_fast.py`）

- `-j` 默认改为 `0`＝自适应：单会话吃满 CPU（clamp 到 16），多会话按活跃
  构建数（数 `.reclaim-lock`）平分，避免 N 会话各开 16 线程互抢核。
  `EXBAR_JOBS` 环境变量可整体钉住（CI / 排障）。实测 2 个会话持锁时自动降到 5。
- 链接器在有 `ld.lld.exe` 时用 lld（`-fuse-ld=lld`）。**链接器不进配置签名**——
  换链接器不改变目标代码语义，不该触发全量重编。

### B. 跨会话共享 obj 缓存（`tools/objcache.py`）

内容寻址缓存：键 = `sha256(源内容) + 配置签名 + pch_deps_hash`。

- **命中即硬链接**：objdir 与缓存指向同一物理文件，零额外磁盘；某会话删自己
  objdir 的链接不影响缓存，缓存过期删条目也不影响已链接 obj（链接计数）。
- **键包含全部输入，内容寻址**：源码/flags/公共头任一变 → 键变 → 必重编，
  绝不会拿到过期 obj。这比 mtime 判据可靠（不看时间戳，只看内容）。
- **PCH 用语义哈希而非二进制哈希**：各会话独立生成的 `common.h.gch` 因内嵌
  路径/时间戳而二进制不同，但声明集相同；用二进制哈希会让每个会话键都不同、
  缓存形同虚设（实测踩过：命中 164/165，差的那个就是 PCH hash 不同）。
- **并发写安全**：先写临时文件再 `os.replace` 原子落键。
- **缓存是加速不是资产**：`obj_cache/` 加入 `reclaim.py` 的 `KEEP_DIRS`
  （不能当残留回收）；陈旧条目由 `objcache.prune()` 按 mtime 自管，默认 14 天。
- `--no-objcache` 可整体关闭（排障用）；任何缓存异常都降级为"没命中→正常编译"，
  绝不影响构建结论。

**实测效果**（两个全新会话，同源码）：

| | 会话 A（填缓存） | 会话 B（全新 objdir） |
|---|---|---|
| 缓存命中 | 0/165 | **165/165** |
| 总耗时 | 29.5s | **4.6s** |

第二个及之后的会话从 ~30s 降到 ~5s，提速约 6 倍。缓存池稳定 165 TU / ~70 MB。

**正确性验证**：改 `str.h` 内容 → 键全变 → 0/165 命中 → 全量重编（安全）；
改回后重新命中旧键。两个会话编出的 exe 大小完全一致，仅调试信息内嵌路径不同。

## 3. 评估后决定不做的：PCH 拆分

原计划把 `common.h` 里的 4 个本地头拆出 PCH 以缩小重建面。实测后发现**收益为负**：

- PCH 真实依赖面只有 5 个头（`common.h` + `identity/log/nav_path/str`），已很窄；
- 合并 B 之后，改公共头会正确触发键变化重编——这正是语义所需，不是缺陷；
- 把 4 个头移出 PCH 会让它们在多个 TU 里重复解析，反而变慢，还可能破坏
  "头文件自足"约定（AGENTS §3）。

所以保留现状。这是基于实测的工程判断，不是遗漏。

## 4. 操作速查

```bash
bash build.sh                    # 增量构建，并行度自适应
bash build.sh -j 4               # 显式钉住并行度
EXBAR_JOBS=4 bash build.sh       # 环境变量钉住（CI / 排障）
bash build.sh --no-objcache      # 关闭跨会话 obj 缓存
python tools/objcache.py         # 查看缓存统计
python -c "import sys;sys.path.insert(0,'tools');import objcache;objcache.prune()"  # 清陈旧缓存
```
